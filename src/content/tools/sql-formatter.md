## Why Client-Side Matters

A SQL query often contains the private anatomy of a system: table names, column names, filters, and business logic that reveal how a database is built. Pasting that into a server-based formatter means handing your schema to a stranger. This tool formats entirely in your browser. Your queries, your table names, and your database structure never leave your device, never pass through a server log, and are gone when you close the tab. Formatting is a local job, and here it stays local.

## Step-by-Step Guide

Paste your raw or minified SQL query into the text area — a single line of compressed SQL, a query copied from a log file, or a block straight from your code. Click "Format SQL" to beautify it, or "Minify SQL" if you need the compact version instead. The formatted query appears with keywords capitalised and clauses indented, so you can read the structure at a glance. Review the result, check that the logic is untouched, and copy it with one click into your database client, your code editor, or your documentation.

## Feature Deep Dive

The formatter standardises the keywords that structure a query — SELECT, FROM, WHERE, JOIN, GROUP BY, ORDER BY, and the rest — into uppercase, which separates them visually from table and column names. Major clauses start on their own lines, and nested parts are indented: subqueries sit one level deeper, and conjunctions like AND, OR, and ON are aligned so the conditions they join are easy to follow. The minifier does the opposite job, stripping single-line comments, multi-line comments, and extra spaces to produce a compact string for embedding in code or a URL. Both operations work on standard ANSI SQL as well as PostgreSQL, MySQL, SQLite, Oracle, and Microsoft SQL Server syntax, so the same tool serves whichever database you use.

## Use Cases

Developers paste in a query that has grown into a wall of text and get back something they can actually debug. Database administrators tidy up queries from slow-query logs before investigating them. Code reviewers format a colleague's SQL so the logic is visible instead of hidden in one long line. Teams writing documentation format example queries so readers can follow them. It is also the quick fix for SQL generated by an ORM or a reporting tool, which often arrives minified and unreadable. Students learning SQL format textbook examples to see how clauses nest, which makes the logic easier to follow than a single-line query.

## Frequently Asked Questions

**Does formatting change what the query does?**

No. Formatting only changes whitespace and the case of keywords. The tables, columns, conditions, and order of operations stay exactly as they were, so the query returns the same results.

**Can I format a query that has a syntax error?**

The formatter works on text, not on a live database, so it will format what you paste without judging whether it runs. It will not fix a broken query or tell you where the error is — that still needs your database client.

**Why are the keywords uppercased?**

It is a long-standing convention that makes a query scannable: keywords stand out in capitals while table and column names stay as written. Your eye finds the SELECT, the WHERE, and the JOIN instantly instead of hunting through a block of mixed text.

**Is my query sent anywhere?**

No. The formatting runs entirely in your browser, with no network traffic at all. Your schema names, filters, and business logic never leave your device.
